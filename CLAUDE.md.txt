## 0-1. 루틴(Scheduled Task) 설정 시 필수 사항
**Unattended 모드 (무인 자동 실행)에서도 작동하려면:**
- `~/.claude/settings.json`에 모든 필요한 도구를 **반드시 허용**해야 함
- 최소한 `"*"` 와일드카드 추가 또는 개별 도구 명시
- MCP 도구뿐만 아니라 `Read`, `Glob`, `Bash`, `PowerShell` 등 빌트인 도구도 포함
- **중요**: Unattended 모드에서는 "허용" 버튼을 눌러줄 사람이 없으므로, settings.json에 없는 도구는 100% 차단됨
- 루틴이 실패하고도 로그를 못 남기는 상황을 방지하려면 `Write`, `Edit` 도구도 반드시 허용할 것
- **[2026-05-27 추가] 환경변수 로드 순서**: 스크립트 시작 시 `~/.claude/settings.json` → `.claude/settings.local.json` 순으로 명시적 로드 후 검증할 것. ANTHROPIC_API_KEY 누락이 가장 빈번한 실패 원인(13회/7일)
- **[2026-05-27 추가] Notion DB ID**: 하드코딩 금지, 환경변수로 분리하고 시작 시 404 방지를 위한 유효성 검증 추가

## 1. 플랜 우선 원칙
- 작업 시작 전 반드시 `plan.md` 작성
- 플랜 포함 항목: 목표 / 접근 방식 / 예상 파일 변경 목록 / 검증 기준
- 플랜 없이 코드 수정 시 → 즉시 중단

---

## 2. 가시성 (눈 달아주기)
- 모든 작업 단계에서 로그 출력 필수
- 로그 결과를 보고 스스로 판단: 원하는 결과인가? → Y면 진행 / N이면 수정 후 재시도
- 스크린샷 또는 출력 결과는 반드시 보존

---

## 3. 점진적 컨텍스트
- 한 번에 모든 정보를 읽지 않는다
- 필요한 정보는 목차를 통해 해당 섹션만 찾아서 읽는다
- 컨텍스트 과부하 시 요약 후 핵심만 유지

---

## 4. 강제 검증 (CI/CD)
작업 완료 후 아래 순서대로 반드시 실행:
1. 단위 테스트
2. 린트(Lint)
3. 빌드 테스트

→ 하나라도 실패 시 다음 단계 진행 금지
→ 실패 로그 확인 후 스스로 수정 → 재실행

---

## 5. 워크트리 원칙
- 메인 브랜치 직접 수정 금지
- 작업은 반드시 별도 브랜치 또는 Git Worktree에서 진행
- 모든 테스트 통과 후에만 메인에 머지

---

## 6. 커밋 규칙
- 커밋 메시지 형식: `[type]: 변경 내용 한 줄 요약`
- type 예시: feat / fix / refactor / test / docs
- 커밋 전 Husky 훅 자동 실행 → 실패 시 커밋 차단

---

## 7. 절대 금지
- 플랜 없는 코드 작성
- 테스트 없는 머지
- .env 파일 수정
- git add -A 사용
- 실패 로그 무시하고 강행

---

## 8. 컨텍스트 한도 도달 시
작업 중단 금지.
현재 진행 상황 저장 → 요약 후 계속 진행.

## 9. 트리거: "루틴으로 만들어줘"

사용자가 **"루틴으로 만들어줘"** 라고 말하면 즉시 아래 3단계를 직렬 실행한다.
코드 작성 전 플랜 없이도 이 루틴은 예외적으로 바로 실행한다.

### Agent A — 로그 수집
- 최근 7일 실행 로그 수집: `~/.claude/notion_beeminder.log`
- 수집 항목: 실행 시각, 성공/실패 여부, 에러 메시지, 실행 소요 시간
- 출력: `~/.claude/routine_analysis/raw_logs_YYYYMMDD.json`

### Agent B — 패턴 분석
Agent A 결과를 입력으로 받아 분석:
- **약점**: 자주 실패하는 조건, 에러 패턴
- **강점**: 안정적으로 작동하는 부분
- **사용자 선호**: 성공 시 패턴에서 유추
- **추천 규칙**: 개선 가능한 설정 변경 목록
- 출력: `~/.claude/routine_analysis/pattern_YYYYMMDD.json`

### Agent C — CLAUDE.md 자동 패치
Agent B 결과를 입력으로 받아:
1. 현재 `CLAUDE.md.txt` 백업 → `CLAUDE.md.txt.backup_YYYYMMDD`
2. 분석 결과 기반으로 관련 섹션 자동 업데이트
3. 새 추천 규칙이 있으면 이 섹션 하단 "## 9-1. 학습된 규칙" 에 누적 추가
